## Chosen fix: edit_file: accept a list of atomic edits so a whole fix lands in one call

File: `mend/worker.py`

In mend/worker.py, change the edit_file tool so that one call can carry several replacements.

1) In TOOLS, change the edit_file input_schema:
- Keep `path` (required).
- Add an `edits` array (minItems 1). Each item is {old: string, new: string}, both required, additionalProperties false.
- Keep top-level `old`/`new` as optional for backward compatibility.
- Make only `path` required.

2) Rewrite the edit_file description, keeping the existing exact-match, uniqueness and TAB-prefix rules and appending _AUTO_TEST_NOTE. Say:
- "Put EVERY change the fix needs into one call's `edits` list: for example, a renamed or newly imported name together with every line that uses it, or a helper import together with the code that calls it."
- "Edits are applied in order. If any edit fails, none are written."
- "Partial fixes waste a full test cycle."

3) In the edit_file handler:
- Build `pairs = edits or [{old, new}]`. Raise ValueError if no pairs are given.
- Read the file text once and apply each pair in sequence to an in-memory string, using the same count logic (0 / 1 / >1) as now.
- For the 0-match case, refactor `_edit_ignoring_whitespace` so it takes and returns text instead of writing the file. It should still raise the same detailed errors, prefixed with the failing edit's index (e.g. `edit 2: ...`).
- Write the file only after all pairs succeed.
- Return one summary line per edit.

No change to the loop is needed: one successful edit_file call still triggers one automatic full test run.

Why it is general: In all three slow runs the cause was the same: the worker spread one logical change (an import or definition and its use) over two turns. Each partial edit burned a test cycle that could not pass. A batched, atomic edit makes it natural to submit the complete change set in a single tool call. The tool description names the common case of a definition plus its uses. This applies to any multi-location bug in any codebase and does not depend on the model following a 'same turn' instruction it has already ignored.

## Proposed neatlogs regression guard

`Mend: slow solve (5+ turns)`: regex `["']turns["']\s*:\s*([5-9]|1[0-9])\b` on the output of `solve_task` spans. Flags runs that needed 5 or more turns. Here that typically means the fix was applied as several partial edits in separate turns, each one followed by a failing automatic test run.
