## Chosen fix: Loop: seed file listing and auto-finish when full suite passes after an edit

File: `mend/worker.py`

In solve_task, make two changes.
(1) Seed the file listing. Before the while loop, compute `files = list_files(work)`. Build the first user message as `f"Bug report: {report}\n\nProject files:\n{files}"` so the model never spends a turn on list_files.
(2) Auto-finish on green.
- Track `edited = False`.
- In the tool-dispatch loop, set `edited = True` whenever an edit_file or write_file call returns without error.
- After building tool_results for a turn, check whether this turn contained a run_tests call with no pattern or an empty pattern whose result content starts with 'PASSED'. If it did and `edited` is True:
  - append the tool_results message as usual;
  - set result['stop'] = 'suite_passed';
  - set result['summary'] to the joined text blocks of that turn's assistant response, or 'Fixed the bug; full test suite passes.' if that text is empty;
  - return result immediately, without another model call.
Keep all other behaviour unchanged (MAX_TURNS, error handling, tool definitions).

Why it is general: A passing unfiltered test suite is exactly the success criterion solve() uses. Any turn after it (re-reading, re-verifying, writing a summary) is pure overhead for every bug. All three traces spent 1-2 turns there, and prompt instructions alone did not stop the model. Giving the file listing up front also removes a mandatory orientation step on every task without assuming anything about the library.
