## Chosen fix: Loop: auto-run full test suite after any turn with a successful edit; finish on green

File: `mend/worker.py`

In solve_task, after the per-block tool loop builds tool_results and before appending the user message, add an automatic verification step:
(1) Track `edited_this_turn = True` whenever an edit_file/write_file call in this turn succeeded, and `ran_full_suite_this_turn = True` whenever the model itself called run_tests with no pattern in this turn.
(2) If edited_this_turn and not ran_full_suite_this_turn, call `auto = run_tests_tool(work)`. This is the existing traced span, so it shows up in the trace. Append a text block to tool_results after all tool_result blocks: {"type": "text", "text": "Automatic full test run after your edit(s):\n" + auto}. If auto.startswith("PASSED"), set suite_passed = True.
(3) Keep the existing early exit: `if suite_passed and edited` returns with stop='suite_passed'.
(4) Update the edit_file and write_file tool descriptions in TOOLS to say: "After any turn containing a successful edit, the full test suite is run automatically and its result is returned to you; do not call run_tests yourself to verify. If the change needs several edits, make them all in this same turn so the automatic run sees the complete fix."
Do not change MAX_TURNS or other tools.

Why it is general: Every bug fix ends with an edit followed by a verification run. Folding that run into the edit turn saves one model turn on every task, along with its full-context LLM call. Telling the model that the suite runs after each edit turn also nudges it to batch multi-part edits into one turn, since a partial edit produces a visible failure. Nothing here depends on the library, a module or a particular bug, and it builds on the kept stop-on-green rule rather than repeating it.
