## Chosen fix: edit_file: on a miss, show the exact current text of a whitespace-insensitive match; make the read_file prefix unambiguous

File: `mend/worker.py`

1) In read_file, change the line-number prefix so it cannot be confused with indentation. Use a tab separator: f"{start + i}\t{line}" instead of f"{start + i}: {line}". Update the read_file tool description to say: 'Each line is prefixed with its number and a TAB; the code starts right after the TAB.' Update the edit_file description to say 'do not include the line-number-and-TAB prefix'.

2) In edit_file, when count == 0, try a fallback before raising.
- Split `old` into lines and strip trailing newlines. Compare each line with .strip() against every same-length window of consecutive lines in the file (also stripped).
- If exactly one window matches, apply the edit to that window, but only if every line of `old` differs from the file only in leading or trailing whitespace. To do this:
  - Compute the indentation delta between the first non-blank line of `old` and the first non-blank line of the window.
  - Re-indent every line of `new` by that same delta: add spaces if the file is more indented, remove up to that many leading spaces if it is less.
  - Replace the window lines with the re-indented `new` lines and write the file.
  - Return f"edited {path}: replaced N line(s) with M line(s) (note: your `old` had different indentation than the file; matched ignoring whitespace and re-indented `new` by {delta:+d} spaces)".
- If more than one window matches, raise ValueError listing the starting line numbers and saying to include more context.
- If none match, find the file line most similar to the first non-blank line of `old` using difflib.get_close_matches on stripped lines. Raise ValueError("`old` not found. Closest line in the file is line {n}: {repr(actual_line)} (leading spaces: {k}); your first line was {repr(old_first_line)} (leading spaces: {j}). Copy the text exactly as shown.").
Keep the existing count > 1 error unchanged, and keep the tests-directory guard.

Why it is general: Exact-match string editing is the worker's only way to change existing code. Any whitespace slip (indentation miscounted, a prefix character copied, tabs vs spaces) currently produces an opaque error that a cheap model retries blindly until it runs out of turns, as in task 28. Matching while ignoring whitespace, with re-indentation, plus a precise diagnostic, removes this failure mode for every bug in every file. An unambiguous read prefix stops the mistake at its source.
